# Googleドライブへのレポート保存

レポートの保護者向けPDFとコーチ向けPDFを、共有ドライブ内のフォルダにも保存します。代行のコーチ・SV・管理者が、慣れた Googleドライブでコーチ向けのレポートを見られるようにするためです（共有コードでの取り込みと併用できます）。

## 仕組み

### フォルダ構成

```
保存先フォルダ（DRIVE_ROOT_FOLDER_ID）
└─ さとうコーチ（sato）                    … オーナーのコーチごとのフォルダ
   └─ はるとくん_7K3Q                       … お子さまごとのフォルダ（名前＋短縮ID）
      ├─ 育ちマップ_はるとくん_7K3Q_第1回.pdf          … 保護者向け（4枚）
      └─ 育ちマップ_はるとくん_7K3Q_第1回_コーチ用.pdf  … コーチ向け（4枚＋メニュー提案）
```

- コーチのフォルダ名には、表示名が同じコーチを見分けられるようにメールアドレスの @ より前を添えます（フォルダ名は共有された人に見えるため、ドメインまでは出しません）。
- お子さまのフォルダは **オーナーのコーチのフォルダの下** に置きます。オーナー移譲コードで取り込まれると、新しいオーナーのフォルダへ移ります。
- フォルダ名・ファイル名は表示用です。アプリは ID で覚えているので、お名前や表示名を変えても次の保存で名前が追いつきます。

### 保存のタイミング

- レポート画面を開いたときに、Drive に保存した版がいまのレポートより古ければ、自動で保存します。「レポートを作る／更新」のあとはレポート画面に移るので、実質その直後に保存されます。
- 失敗しても、次に誰かがそのレポートを開いたときにやり直します。レポート画面の「もう一度保存する」からも送り直せます。
- 保存には十数秒かかります。レポート画面では操作バーの下の帯に、いまの段階（保護者向けPDF → コーチ向けPDF → Driveへ保存）と進み具合を出します。保存中にほかの画面へ移っても保存は続き、画面右上のパネルに進み具合と結果が出ます。画面を閉じても、サーバーは保存を最後まで行います。
- 段階ごとの所要時間は Cloudflare のログに `report_drive_timing` で残ります。進み具合のバーの伸び方（Web の `DRIVE_STEP_EXPECTED_MS`）は、この実測に合わせて直します。
- レポートを更新したときは同じファイルを上書きします。リンクは変わらず、前の版は Drive の「版を管理」に残ります（Drive の既定では30日・100版まで）。

### 権限

- アプリが付ける権限は **オーナーのコーチ → 自分のコーチフォルダの閲覧者** だけです（共有の通知メールは送りません。サイトのリンクから開きます）。
- SV・代行のコーチへの共有は、オーナーのコーチか全体管理者が Drive 上で行ってください。SV のように複数のコーチを見る人は、コーチのフォルダごと共有すると配下のお子さまもまとめて見られます。
- 保存先フォルダの管理者（共有ドライブのメンバー）は、配下のすべてを見られます。
- 取り込んだだけのコーチにも、子どもページに「Googleドライブのフォルダ」のリンクを出します。権限が無い場合は Drive の画面で「アクセス権をリクエスト」できます。

### サイトからのリンク

| 画面 | リンク | 開く先 |
| --- | --- | --- |
| 担当の子ども一覧 | Googleドライブ | 自分のコーチフォルダ（最初の保存後に表示） |
| 子どもページ | Googleドライブのフォルダ | お子さまのフォルダ |
| レポート画面 | フォルダを開く／コーチ向けPDF（Googleドライブ） | お子さまのフォルダ／その回のコーチ向けPDF |

保護者向けPDFは、これまでどおりレポート画面の「保護者向けPDF」からダウンロードできます。コーチ向けPDFのダウンロードボタンは、Drive への保存を設定していない環境（ローカル）だけに出ます。

## 初回の設定

保存先フォルダの ID は `apps/api/wrangler.toml` の `DRIVE_ROOT_FOLDER_ID` に設定済みです（本番・ステージングとも `1JmKflTCBP00vSpz3vClqaud1ObPy9KGz`）。残りは、書き込みに使う **サービスアカウント** の用意です。

サービスアカウントは、人ではなくプログラムが使う Google アカウントです。鍵（JSON ファイル）を持つプログラムだけがそのアカウントとして操作でき、共有されたフォルダにしか触れません。

### 1. Google Cloud のプロジェクトを用意する

1. heyasupo.net の Google アカウントで <https://console.cloud.google.com/> を開く
2. 画面上部のプロジェクト選択から「新しいプロジェクト」を作る（例：`heyasupo-assessment`）。既存のプロジェクトを使ってもよい
3. 作ったプロジェクトを選んだ状態で「APIとサービス」→「ライブラリ」を開き、**Google Drive API** を検索して「有効にする」

料金はかかりません（Drive API は無料で、課金の設定も不要です）。

### 2. サービスアカウントを作る

1. 「IAMと管理」→「サービスアカウント」→「サービスアカウントを作成」
2. 名前を入れる（例：`assessment-drive`）。ID とメールアドレス（`assessment-drive@<プロジェクトID>.iam.gserviceaccount.com`）が自動で決まる
3. 「ロール」と「ユーザーにアクセス権を付与」は **空のまま** 完了する（Google Cloud 側の権限は要りません。Drive の権限は手順4で付けます）

### 3. 鍵（JSON）を作る

1. 作ったサービスアカウントを開き、「鍵」タブ →「キーを追加」→「新しい鍵を作成」→「JSON」→「作成」
2. JSON ファイルがダウンロードされる。**これがパスワードに当たるので、チャット・メール・リポジトリに貼らない**

「サービスアカウント キーの作成が無効になっています」と出る場合は、組織のポリシーで鍵の作成が止められています（2024年5月以降に作られた Google Cloud の組織では既定で止まっています）。組織のポリシー管理者に、このプロジェクトだけ `iam.disableServiceAccountKeyCreation`（`iam.managed.disableServiceAccountKeyCreation`）を「適用しない」に上書きしてもらってから、もう一度作ってください。

### 4. 共有ドライブにサービスアカウントを追加する

1. Googleドライブで保存先フォルダが入っている **共有ドライブ** を開き、「メンバーを管理」
2. 手順2のサービスアカウントのメールアドレスを入れ、役割を **管理者** にして追加する（「通知」のチェックは外してよい）
   - フォルダの作成・移動と、コーチへのフォルダ共有を確実に行うために管理者にします
3. 共有ドライブの設定（「共有ドライブの設定」）で、次の2つをオンにする
   - **heyasupo.net 以外のユーザーにアクセスを許可する**（コーチは @gmail.com のため）
   - **メンバー以外のユーザーにファイルへのアクセスを許可する**（コーチは共有ドライブのメンバーにしないため）

保存先フォルダは、マイドライブではなく共有ドライブの中にある必要があります（サービスアカウントは自分の保存容量を持たないため、マイドライブには保存できません）。

Google Workspace の管理コンソールで外部との共有を制限している場合は、「アプリ」→「Google Workspace」→「ドライブとドキュメント」→「共有設定」で、heyasupo.net 以外のユーザーと共有できるようにしてください。

### 5. 鍵を Cloudflare に登録する

ダウンロードした JSON ファイルを、そのまま Secret として登録します。

```bash
# ステージング
pnpm --filter @papamo/api exec wrangler secret put GOOGLE_SERVICE_ACCOUNT_KEY --env staging < ~/Downloads/<ダウンロードした鍵>.json

# 本番（公開時）
pnpm --filter @papamo/api exec wrangler secret put GOOGLE_SERVICE_ACCOUNT_KEY < ~/Downloads/<ダウンロードした鍵>.json
```

登録が済んだら、鍵ファイルはパスワード管理ツールなど安全な場所に移すか削除してください。鍵を作り直したときは、同じコマンドで登録し直し、Google Cloud で古い鍵を削除します。

### 6. 反映と確認

1. `pnpm db:migrate:staging`（Drive の保存状態を持つ列を追加するマイグレーション `0003_google_drive.sql`）
2. `pnpm run deploy:staging`
3. ステージングでレポートを開き、操作バーの下に「Googleドライブに保存しました」と出ることを確認する
4. 「フォルダを開く」で Drive が開き、保護者向け・コーチ向けの2つのPDFがあることを確認する
5. 担当コーチの Google アカウントで、自分のコーチフォルダが「共有アイテム」から開けることを確認する

## ローカルで試す

既定では保存しません（`.dev.vars` の `GOOGLE_SERVICE_ACCOUNT_KEY` が空のため）。試すときは次の順で設定します。

1. ステージング・本番の保存先と混ざらないよう、同じ共有ドライブの中に検証用のフォルダ（例：`ローカル検証`）を作り、URL の `folders/` の後ろの ID を控える。サービスアカウントは共有ドライブのメンバーなので、追加の共有は要らない
2. `apps/api/.dev.vars` に保存先と鍵を書く。鍵は改行を含まない1行にしてシングルクォートで囲む。次のコマンドなら鍵を画面に出さずに書き込める（WSL では Windows のダウンロードフォルダは `/mnt/c/Users/<ユーザー名>/Downloads`）

   ```bash
   cd apps/api
   sed -i '/^DRIVE_ROOT_FOLDER_ID=/d; /^GOOGLE_SERVICE_ACCOUNT_KEY=/d' .dev.vars
   printf "DRIVE_ROOT_FOLDER_ID=%s\nGOOGLE_SERVICE_ACCOUNT_KEY='%s'\n" '<検証用フォルダのID>' "$(jq -c . <ダウンロードした鍵>.json)" >> .dev.vars
   ```

3. `pnpm --filter @papamo/api dev` を起動し直す（`.dev.vars` の変更を確実に読み込ませるため）。Web は `pnpm --filter @papamo/web dev`
4. ローカルでログインし、レポートを開くと保存が始まる。初回は Browser Run 用の Chrome のダウンロードで数十秒かかる

`.dev.vars` はワークツリーごとに持ちます（Orca で新しいワークツリーを作ると、元のチェックアウトの `.dev.vars` がコピーされます）。自動テストは `.dev.vars` の鍵があっても Drive に書き込みません（テスト用の偽の Drive を使います）。

## 運用上の注意

- Drive 上でお子さまのフォルダを別の場所へ動かしても、次の保存でオーナーのフォルダの下へ戻ります。
- Drive 上でフォルダやPDFをゴミ箱へ移した場合は、次に保存するときに作り直します。
- アーカイブしたお子さまのフォルダはそのまま残ります。
- ステージングのシードや DB の作り直しでは、Drive 上のフォルダは消えません（新しいフォルダが作られます）。検証で溜まったフォルダは Drive 上で消してください。
- 本番を公開するときは、ステージングの検証データと混ざらないよう、ステージング用の保存先フォルダを分けることを検討してください（`wrangler.toml` の `[env.staging.vars]` の `DRIVE_ROOT_FOLDER_ID`）。

## うまく保存できないとき

| 画面の表示・ログ | 主な原因 |
| --- | --- |
| 「Googleドライブの保存先に書き込めませんでした。管理者に共有ドライブの設定を確認してもらってください。」 | サービスアカウントが共有ドライブのメンバーになっていない、または役割が足りない。保存先フォルダがマイドライブにある（ログの理由が `storageQuotaExceeded`。サービスアカウントは保存容量を持たないため、フォルダを共有されていてもファイルを置けない） |
| 「Googleドライブに保存できませんでした。少し待ってから…」 | Drive の一時的な障害、鍵の失効・削除。Cloudflare のログで `api_internal_error`（`report.drive.save`）の `error` を確認する |
| 「通信が途中で切れました。…」 | 保存の途中で通信が切れた（回線・プロキシ）。サーバー側では保存が続いていることが多いので、レポートを開き直すと保存済みになっているか確かめられる。`report_drive_timing` の `outcome` でサーバー側の結果を確認する |
| レポート画面に Drive の表示が出ない | `GOOGLE_SERVICE_ACCOUNT_KEY` が未登録か、JSON として読めない（ログに `google_drive_misconfigured`） |
| コーチが自分のフォルダを開けない | 共有ドライブ・管理コンソールで外部共有がオフ。ログの `google_drive_failed`（`share_coach_folder`）を確認する。共有は次の保存で付け直す |
